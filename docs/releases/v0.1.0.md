# Exoma 0.1.0

First release. Exoma is agent-workflow 3.9.0 repackaged as an installable Python library and
CLI. The commands, contracts, hooks and `.workflow/` workspace are the same; what changes is
how the runtime is installed, invoked and upgraded.

## Install and invoke

- `pip install exoma` or `uv tool install exoma` installs the package; `exoma` is the CLI and
  `python -m exoma` the same entry point. The browser extra is `exoma[e2e]`.
  ([installation](../installation.md))
- Commands take a subcommand (`exoma init`, `exoma explore ...`) or the flag form
  agent-workflow used (`exoma --command init`). `exoma install ...` and `exoma check ...` are
  the old `install.py` and `check.py`. ([reference: install](../reference.md#detail-installer))
- `import exoma` loads nothing but the package itself.

## Workspaces

- `init` records `runtime.python` and `runtime.package_root` instead of a checkout's
  `main.py`/`check.py`; the generated `run.sh`, `inspect.sh` and `check.sh` exec
  `<python> -m exoma` with the package root first on `PYTHONPATH`. The runner names are
  unchanged, so the hook gate still recognizes them.
  ([reference: init](../reference.md#init-in-the-target-project))
- `exoma upgrade` (or `/.upgrade`) takes over a workspace agent-workflow wrote: it removes
  `runtime.agent_workflow_path`, `main_py_path`, `check_py_path` and `tool_dir` and
  regenerates the scripts. It still refuses while a job is running.
  ([reference: upgrade](../reference.md#workspace-upgrade))
- `AGENT_PATH` is no longer read or set; `exoma install --set-env` is gone. `doctor` reports
  an `AGENT_PATH` or recorded checkout path under `runtime_resolver.legacy`.

## Storage

- Job records, the main-session cache and the provider seed move from the checkout's
  `storage/` and `config/` to a per-user data directory (`EXOMA_HOME`, else the platform
  default). Project data stays in `.workflow/data/`. Jobs an agent-workflow checkout recorded
  are not migrated: they belong to that runtime.
  ([reference: workspace layout](../reference.md#workspace-layout))
- The shipped bundle and its manifest live in the package (`exoma/_bundle/`). `doctor`
  judges the manifest's freshness by content hash rather than file times, which an installed
  wheel does not preserve.

## Product strings

- Messages, the installer banner and the skills name Exoma and `exoma` commands instead of
  agent-workflow, `python main.py` and `$AGENT_PATH`. Per-user cache files move to
  `<cache>/exoma/`. The promoted-knowledge schema keeps its `$id` so existing knowledge files
  stay valid.

## Known limits

- Exoma and agent-workflow install hooks and skills under the same names in `~/.claude`;
  installing one replaces the other.
- The package must be installed unpacked (the default for wheels); bundle files are read
  from the package directory.
- Not yet published to PyPI at the time of these notes; install from a built wheel.
