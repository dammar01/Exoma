# Exoma 1.1.1

Candidate preparation for an updater fix release. Commit, tagging and publication remain
separate release actions; this page does not declare the candidate ready to publish. The
`v1.1.0` tag and its notes ([v1.1.0](v1.1.0.md)) are retained.

## Changes

- **macOS guardian cleanup.** On Darwin the final group SIGKILL can return EPERM when the
  group holds only the already-exited, unreaped leader, which previously forced
  `cleanup_failed(signal_kill)` and an unconfirmed cleanup even after a successful reap.
  The failure is now deferred and discarded only when the child's exit was observed before
  the signal, the reap succeeded, and a following signal-0 probe of the group raises
  ESRCH. A present group, a denied or failed probe, a failed reap, a missing exit
  observation, or any non-EPERM signal error keeps the negative receipt. Signal 0 is the
  only signal sent after the reap. Contract: [docs/runtime-contracts.md](../runtime-contracts.md)
  and [docs/reference.md](../reference.md).
- **Windows handoff gate.** GitHub-hosted Windows runners keep the helper inside an outer
  job, so CI skips only the real handoff step there (a runner override through
  `EXOMA_WINDOWS_UPDATE_RUNNER` re-enables it). The handoff on a native Windows host is a
  mandatory release-staging gate in [RELEASE.md](../../RELEASE.md); `publish.yml` cannot
  enforce it. `tools/maintain/native_update_gate.py` runs the full manager/Python matrix
  on a native host and validates the commit-bound reports, but it is a maintainer-run
  check before tagging, not a publication barrier. Production worker admission is unchanged: remaining job membership still
  refuses before mutation, and no restrictive-host refusal is converted into a pass.

## Validation

The `self-update` source suite covers the guardian matrix (exit 0/7 with post-reap
absence, group present, probe denied or failed, reap failure, missing observation,
owner/SIGTERM failure, non-EPERM kill error) with exact event ordering. Darwin and native
Windows behavior were not reproduced locally; they depend on CI and on the staging gate
above. Follow [RELEASE.md](../../RELEASE.md) for the remaining gates.
