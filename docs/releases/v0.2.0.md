# Exoma 0.2.0

Security and identity release. Choosing a provider without a read boundary is now confirmed
where it is chosen instead of through an opt-in variable, secret files are found by name and
named where the risk is reported, the agy guard sees an ignored `.env` change, environment
variables move to the `EXOMA_` prefix, and every shipped instruction file is in English.

## Security

- Selecting `codex` or `agy` as the second agent needs no variable: `AI_PROXY_AGY_OPT_IN` is
  gone. The `/.provider` picker shows the provider's boundary (codex can read every file, agy
  can read and write) and asks for confirmation before applying; every other way of selecting
  returns the same warning in `meta.warnings`. The confirmation is prompt-level, not enforced
  by the runtime.
  ([reference: choosing a provider](../reference.md#choosing-a-provider--and-its-security-consequences))
- `doctor` lists the project files that match the secret patterns (ignored files included,
  names only) in `checks.second_agent_read_boundary.secret_files`, and its read-boundary
  warning names them.
- The agy guard also compares the size and modification time of every file matching the
  secret patterns, so a change to a `.gitignore`d `.env` is reported as `secrets_changed`.
- A threat model in [security.md](../security.md): protected assets, trust boundaries,
  accepted risks, and residual risks (read confinement for codex/agy is not implemented).

## Evidence

- A turn that ends with a `[PLAN]` or `[ANALYSIS RESULT]` built on a plan/analyze run, without
  any `Read` of an anchor that run cites, gets an `[ANCHOR CHECK]` note, once per run. It is a
  warning recorded by the `task-events` hook, whose PostToolUse matcher now includes `Read`.
- [why-not-subagent.md](../why-not-subagent.md) explains why evidence goes to a second agent,
  with the measured figures and their limits.

## Windows

- A delegated worker no longer flashes a terminal window when the runtime runs from a venv
  (for example `uv tool install exoma`). Workers and the graph-refresh worker were started with
  `DETACHED_PROCESS`, under which Windows ignores `CREATE_NO_WINDOW`; a venv interpreter then
  opened a visible console. They now start in their own process group with a hidden console.

## Naming

- Every runtime knob is read from `EXOMA_<NAME>`; the old `AI_PROXY_<NAME>` spelling is still
  read as a fallback, and `doctor` lists any still set (`checks.legacy_env`) — only names the
  runtime actually reads.
  ([reference: environment variables](../reference.md#environment-variables))
- The bundled `CLAUDE.md`, every skill and command wrapper, the agy/codex/opencode `AGENTS.md`
  files and the opencode `wf-*` agents are in English. The NL-map trigger phrases stay as users
  type them. The proxy-failure label is now `[PROXY FAILED]`.
- Decision-record ids (`DEC-xxx`) are removed from the shipped instructions, skills, hook
  modules and launchers; those records live in agent-workflow.

## Upgrading

- A codex or agy workspace keeps working; an `AI_PROXY_AGY_OPT_IN` or `EXOMA_*_OPT_IN` you set
  is no longer read and can be removed.
- Rename `AI_PROXY_*` variables in your shell profile when convenient; both spellings work.
- `exoma install --apply` replaces the bundle; the hook settings entry for `task-events` is
  replaced with its new matcher.
