# Exoma 1.2.0

## Changes since 1.1.2

- A uv-based `exoma update` checks Chromium for the Playwright package selected by uv.
  The refresh can provision the matching browser when updating from the released 1.1.2
  worker. [Installation and recovery](../installation.md)

- Execution and verification can record a test tier, the behaviors each command covers,
  and work deferred to release staging. The verification worker checks the selection
  against the prepared project inputs. A change of worker identity keeps the selection
  valid. A change of project inputs requires a new selection. Older requests with just
  commands and a reason remain supported. [Verification reference](../reference.md)
- Browser verification can admit a changed strategy after repeated application failures.
  Removing an assertion leaves a coverage gap visible to the reviewer and the CLI. A
  passing browser run with this gap returns exit 2, including through a stored job result.
- Browser retries can prove a restored dynamic title or a retained assertion for which
  all DOM selectors previously missed. Matching uses the observed page, predicate and
  relevant placeholder inputs. Older receipts without enough evidence remain open.
  [Browser evidence contract](../runtime-contracts.md)

## Release qualification

This is a worktree candidate. Qualification requires the exact final clean commit,
including the metadata and release notes. Record CI for Linux, macOS and Windows,
wheel and sdist installation, Chromium smoke, real-provider E2E, the six native Windows
strict handoff cells, maintainer real use, and staging in agent-workflow against that
commit. [Release procedure](../../RELEASE.md)

For browser upgrade qualification, supply a local wheelhouse with `before/` containing
the published Exoma 1.1.2 wheel, Playwright 1.65.1 and its dependencies. In `after/`
place Playwright 1.65.2 and its dependencies for the same platform and Python. Set
`EXOMA_UPDATE_BROWSER_WHEELHOUSE` to the parent and `EXOMA_UPDATE_WHEEL` to the
candidate wheel, then run `python tests/run.py --only self-update` on a host supporting
independent handoff. uv resolves packages offline. The isolated Chromium cache needs
browser downloads or a configured mirror. Record the candidate wheel hash, successful
loopback smoke after the update, and the separate warm-cache update against the release SHA.
