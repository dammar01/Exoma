# Exoma v1.3.0

## Execution-scoped verification follow-up

- Standard delegated verification tracks findings across rounds in execution `finding_history`, passing up to 32 open findings per round sidecar and reading optional `[FOLLOWUP]` JSON lines before `[VERIFICATION]`.
- Follow-up events report `reason_code` diagnostics (`closure_accepted`, `followup_missing`, `assertion_unmatched`, `fresh_pass_missing`, etc.) and carry `last_reason_code` forward to subsequent rounds.
- Obligations bind assertion receipts (`assertion`, `equivalent_assertion`, and `EXOMA_CASE_V1` case continuity), preserve `VERIFY_FAILURE_MARKER` across interrupted batches, propagate `case_ambiguous`, and persist durable pre-checkpoint job snapshots for recovery.

See [execution-scoped verification findings](../runtime-contracts.md#execution-scoped-verification-findings) and [verification follow-up](../reference.md#linking-later-evidence-to-an-open-finding).

## Runtime threads, attachments, and output

- Provider threads reset on the 200k input token ceiling or degraded outcomes (`confidence: low` with `in_scope_unreachable` or `early_stop`).
- Unreadable or out-of-root attachments fail preflight (`unreadable_attachment`), while shallow early stops and readable `in_scope_unreachable` responses trigger one full-task continuation.
- Delegated CLI commands archive full results to session `result.json` and return a compact JSON pointer on stdout; `/.doctor` reports invalid MCP keys in Codex `config.toml`.

## Workflow, session, and host gates

- `[VERIFICATION]` separates non-blocking `supporting_gaps` from blocking `not_verified`, and `_PATH_SEG` / `_REF_ATOM` regexes avoid exponential backtracking.
- `policies.subagent_fanout_enabled` now defaults to `false`; explicit parallel sub-agent fan-out is opt-in via `/.fanout` (`$exoma-fanout` on Codex).
- `clarify` plans require non-empty `open_questions`, execution scope rejects `.workflow/` paths, and `execute-end` rejects no-op runs (`execution_no_changes`).
- All four main-agent hosts enforce verify read-only/replay locks and post-failure read-only guards (`verify_readonly`, `verify_replay`, `verify_failed_readonly`). Codex adds lazy `UserPromptSubmit` binding, and the CLI enforces registered sessions (`session-init`).
