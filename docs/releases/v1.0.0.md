# Exoma 1.0.0

The first stable release, and a breaking one for the installer. `exoma install` now writes
without `--apply` and takes the host as its argument; OpenCode joins Claude Code, Agy and Codex
as a main-agent host, and Claude Code joins OpenCode, Codex and Agy as a second agent. Each host
keeps its own second-agent choice, picked at install from the provider CLI's live model list. A
session can be exported, redacted, with its second-agent results and a review, for studies run
on real work. Semantic versioning applies from here: the CLI, the config keys and the documented
runtime contracts change incompatibly only in a major release.

## Upgrading from 0.3.0

- `exoma install` **writes**. Use `exoma install --dry-run` to preview. `--apply` on an install
  is accepted with a notice; `--rollback` and `--uninstall` still preview until `--apply`.
- Name the host as an argument: `exoma install claude|agy|codex|opencode|all`. `--host <name>`
  still works with a deprecation notice. **`both` is gone**: use `all`, or name one host.
- Your earlier second-agent choice carries over: the first 1.0 install copies the shared
  `second_agent.seed.json` selection into each chosen host's new seed. Existing projects keep
  their own `.workflow/second_agent.json`.
- OpenCode's second-agent subagents are renamed `wf-*` → `exm-*`. The install removes the old
  files it wrote (edited ones are kept and reported). The `wf-*` allow entries 0.x merged into
  `permission.task` in your `~/.config/opencode/opencode.json` stay; they are harmless, and you
  can delete them.
- `exoma update` runs the new install form for you.

## Install

- `exoma install [claude|agy|codex|opencode|all]` with `--dry-run` to preview. From a terminal
  every install asks each choice a flag did not state (hosts, intent mode, browser extra, Agy
  allow rules, provider updates, second agent per host), the stored one as the default, so Enter
  keeps it. `--no-input`, a run without a terminal, and `exoma update` ask nothing and keep the
  stored choices. Ctrl+C at a question stops the install before anything is written.
  ([reference: install choices](../reference.md#detail-install-choices))
- The second agent is chosen **per host**: one `second_agent.seed.<host>.json` each, and each
  host's `/.init` runs `exoma init --host <host>` so a project starts from the choice of the host
  that set it up. ([reference: seeds](../reference.md#detail-installer))
- The installer's model menu is the live catalog the `/.provider` picker already used: what the
  installed CLI lists now, newest first, with the bundled shortlist as the fallback.
- The browser extra stays out unless `--with-e2e` is given or, from a terminal, its question is
  answered yes (the default is no); a check now guards that default.

## Tests run during /.execute, reused by /.verify

- `run.sh test --session <id> --task '<command>'` runs allowlisted test commands under the
  /.verify policy and records each outcome with a reuse identity (the Git tree's content,
  `.workflow/config.json`, listed environment variables and ignored files). A /.verify that
  requests the same command on an unchanged identity reports that pass as reused instead of
  running it again; once one of its commands runs, the rest run too. Content is compared as Git
  stores it, so an edit Git's line-ending conversion undoes is not a change.
  ([reference: verify_mode](../reference.md))
- `plan-record`, `execute-begin` and `execute-end` snapshot the tree, so `execute-end` names the
  files the execution changed even on a tree with uncommitted edits, and flags those outside the
  plan's scope, Bash writes included; a later verify names edits made after `execute-end`.
  ([reference: plan and execution state](../reference.md#plan-and-execution-state))

## Codex hooks on Windows and POSIX

- Codex runs a Windows hook under `powershell -Command`, where the command written by earlier
  builds was a parse error: every hook exited 1 while `--check` reported READY. Commands now open
  with `&` and single-quote their paths in both shells, so `$`, backticks and `'` in a home path
  stay literal. `--check` and doctor flag the old form, an install repairs it (trust the changed
  handlers again with `/hooks`), and uninstall keeps the script while a custom handler names it.
  ([reference: hosts](../reference.md#hosts))

## OpenCode as a main-agent host

- `exoma install opencode` installs the `EXOMA-OPENCODE-HOST` block in
  `~/.config/opencode/AGENTS.md` (beside the second-agent block), the contract and every workflow
  command as an `exoma-<name>` skill, and a plugin shim, `plugins/exoma.js`, that hands prompts
  and tool calls to `opencode-host.py`. The gates are the shared `workflow_policy` decisions, as
  for every other host; the plugin does nothing in a second-agent process.
  ([reference: hosts](../reference.md#hosts))
- The plugin subscribes only to `chat.message`, `experimental.chat.system.transform` and
  `tool.execute.before`: the first prompt binds the session, and the status guard is not
  registered there. OpenCode documents `session.created` and `session.idle` events; whether
  they can stand in for a session-start and end-of-turn hook has not been verified.
- Restart OpenCode after installing: plugins load at startup.
- An OpenCode second-agent call carries `WORKFLOW_AGENT_ROLE=second_agent`, so the host plugin
  stays off in it when OpenCode is both your host and your second agent.
- Checked live on OpenCode 1.19.4: the plugin loads, `chat.message` and
  `experimental.chat.system.transform` both receive the session id, and the first prompt binds
  the session. The tool gate (`tool.execute.before`) is covered by the hook's own checks; it was
  not observed refusing a model's tool call in a live session.

## Claude Code as a second agent

- `provider: claude` runs `claude -p` with only `Read`, `Grep` and `Glob`, no settings sources
  (so none of your hooks, permission rules, MCP servers or CLAUDE.md), the prompt on stdin, and
  stream-JSON output. Writes are impossible; reads are not bounded, like codex and agy, so it is
  a trusted provider. Works with a subscription login. Its contract is installed as
  `~/.claude/exoma/second-agent.md`, never into your `~/.claude/CLAUDE.md`.
  ([reference: choosing a provider](../reference.md))

## Same CLI as host and second agent

- A second-agent process (`WORKFLOW_AGENT_ROLE=second_agent`, set by every provider adapter)
  that asks the runtime to delegate, queue or run a job, or change execution state is refused
  with `recursion_refused` before any side effect; read-only commands stay open. A guard against
  recursion, not a security boundary: an agy child can unset the variable.
  ([reference: error_type](../reference.md#error_type))
- New offline checks cover the marker on every adapter's child, Claude-on-Claude settings
  isolation, the OpenCode plugin's marker check, and session export picking the host transcript
  when host and child are the same CLI.

## Session export

- `exoma session export <MAIN_SESSION_ID>` writes a redacted zip: the session's prompts,
  answers and archived evidence, its usage and audit rows, the host transcript where the host
  records one (Claude Code, Codex), and a review the participant fills in.
  ([reference: session export](../reference.md#session-export))
- [Experiment protocol](../team-guide/experiment-protocol.md): how a team runs a light-touch
  study on real work with it.

## Non-ASCII file names and job-store errors

- The files an execution changed (`execute-end` `changed_files` / `outside_scope`) and the
  files syntax verify checks are read from Git as bytes, so a name such as `café.py` arrives
  as the file system spells it. On Windows it came back in the locale's code page
  (`cafÃ©.py`), fell outside the plan's scope, and syntax verify skipped it.
- A job-store error that is not a permission refusal (a full disk, an I/O error) now carries
  `meta.reason: job_store_write_failed` without the sandbox-grant advice; doctor's job-store
  fix names `exoma install --check` for the grant itself.
  ([reference: Hosts](../reference.md#hosts))

## Known limitations

- **Codex as host on a `workspace-write` sandbox cannot submit delegated jobs until the storage
  directory is granted.** The global job store lives under the per-user data directory's
  `storage/`, outside the project, and every delegated call writes it from the host's process (CASE-034, a record in
  agent-workflow, observed on Windows). An install whose hosts include `codex` writes the grant
  into `~/.codex/config.toml` as a managed block (`# EXOMA-CODEX-GRANT:START` / `END`), and
  `--check` reports it missing, and a stale block, one beside a table of the user's, or unpaired
  markers as drift. It stays a manual step when the file already holds a
  `[sandbox_workspace_write]` table of the user's: the install leaves the file alone and prints
  the snippet to add. Until the grant is in place the refusal comes back as `job_submit_error`
  with `meta.reason: job_store_not_writable` and the `writable_roots` snippet for this machine,
  doctor reports `checks.job_store_writable` (`NOT_READY` when refused), and `EXOMA_HOME` is the
  other way out. The grant covers `storage/` only, so the data directory's `.env` stays out of
  the sandbox's reach.
  ([reference: Hosts](../reference.md#hosts), [limitations](../limitations.md))

- OpenCode and Agy transcripts are not collected by the export.
