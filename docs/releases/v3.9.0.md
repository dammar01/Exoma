# v3.9.0

Evidence quality and the execute chain. Anchor certification now covers every citation
instead of the first forty, and only in-scope gaps lower confidence. Facts validate every
anchor, rank by weighted overlap, keep what is used, and are counted per call. Promoted
knowledge joins the evidence reuse identity and cannot be pointed outside the project. The
plan → `/.execute -y` → `/.verify` chain becomes runtime state, with hooks that block the
deterministic gates and warn on the rest.

Detail: [`docs/reference.md`](../reference.md) — "Response envelope", "Fact store", "Plan and
execution state", "`.workflow/config.json`"; decisions: DEC-064, DEC-065, DEC-066, DEC-067,
DEC-068.

**Behavior changes after install:**

- **Anchors** (DEC-064, CASE-024). Up to 200 distinct citations are certified; the first 40
  are still the ones stored for reuse. `digest.anchors` and `evidence_ref` carry
  `scanned_all`; a scan that stopped early caps confidence at `medium` even when every
  scanned citation certified. `meta.uncertified_anchors` names refs that did not certify,
  and each `meta.claims` entry has a `ref_status` per ref. Before, a run citing missing files
  after forty good ones read `40/40` and kept its confidence.
- **Scope gaps.** `scope_not_covered` bullets are tagged `in_scope_unreachable`,
  `live_state`, `external` or `out_of_scope` in the output contract. Only
  `in_scope_unreachable` and untagged bullets cap at `medium`; the others are reported in
  `meta.scope_warnings`. Before, any bullet capped, so nearly every explore read `medium`.
- **Knowledge** (DEC-065). The evidence reuse context (schema 3) includes a fingerprint of
  the promoted knowledge a call was shown, so promoting a correction invalidates an identical
  earlier answer; every evidence row written before this release misses reuse once.
  `policies.knowledge_dir` and document ids that resolve outside the project root are
  refused (`knowledge_path_escape`); doctor reports it.
- **Facts** (DEC-066). Every cited anchor must resolve at ingest, and a fact is served only
  while all of them can be placed. Claims over `fact_max_claim_chars` (400) are refused.
  Retrieval scores identifiers 2, words 1, path-only tokens 0.5, ignores English and
  Indonesian function words and generic path segments, and serves at or above
  `fact_min_relevance` (2.0); limits are per role (`fact_relevant_limits`: exploration 3,
  reasoning 4). Promoted knowledge uses the same ranking. Eviction past `fact_max_facts`
  keeps the most used facts. Expect fewer facts ingested and served; the defaults are not
  measured yet (H-021, EXP-013, drafts).
- **Fact telemetry.** Exploration and reasoning results carry `meta.facts`; usage rows carry
  `facts_*` counts on the command's final row; `--command report` has a `facts` section
  (`runtime.fact_lifecycle@1`).
- **Execute chain** (DEC-067, revises DEC-046). New local commands `plan-record`,
  `execute-begin`, `execute-end`. `/.plan` records its plan; a `proceed` with open
  questions, a `solution_path` below `high`, no `files` scope, an option without a `minus`
  or not exactly one recommendation is refused. `execute-begin` needs that plan and the
  user's own `/.execute -y` (a token the prompt hook writes, valid 15 minutes, used once). A
  finished verify writes its verdict to the execution; a syntax-mode verify records
  `syntax_only`.
- **New hooks.** `execution-gate` (PreToolUse) blocks Write/Edit outside the project root
  (temp dir, `~/.claude` and `policies.write_allowed_outside_root` excepted), Write/Edit
  outside an active execution's scope, and `git commit` in a turn where the user did not ask
  for one; paths are compared after resolving symlinks and junctions. `status-guard` (Stop) warns when a reply claims completion while verification is
  `not_run`. `policies.enforcement` = `hybrid` (default) | `warn` | `off`. Writes through
  Bash or scripts are not checked.
- **Graph staleness** reads the same source extensions and skip directories the refresh
  hook scans, so a non-Python project's graph is no longer reported current while the hook
  rebuilds it, and a change under `vendor/` or `storage/` no longer makes one side call the
  graph stale while the other calls it current.
- **Hook payload and Python** (DEC-068). Hooks read their payload from stdin as UTF-8 and get
  it in memory, never through the environment: a Write, Edit or prompt past 32767
  characters crashed every hook on Windows (and the PreToolUse gates then failed open; this
  also affected v3.8.4). A hook that raises exits 0 and logs to
  `~/.claude/hook-errors.log`. The installer pins its interpreter in
  `~/.claude/hooks/python.path`; launchers and generated `.workflow/*.sh` use it. On Windows
  it adds `env.CLAUDE_CODE_GIT_BASH_PATH` so a headless `claude -p` from PowerShell still runs
  the hooks through Git Bash.
- **Forks** (DEC-068). `/branch` and `/fork` (SessionStart `source: fork`) get their own
  `MAIN_SESSION_ID`. Before, a fork was unregistered and `/.execute -y` there was refused; a
  fork has no plan of its parent, so record one before `/.execute -y`.
- **Intent gate** (DEC-068). Only an explicit delegated command (`/.analyze ...`, or the
  slash-command payload) arms the gate; a prompt that only resembles one gets an
  `[INTENT HINT]` and blocks nothing. Pasted content is not classified. An unknown prompt
  `source` approves execute/commit only with the command at the start of the prompt;
  `policies.prompt_sources` extends the known labels. The gate now passes skill reads written
  `~/` or `/c/...` or as one-file `cat`, a background task's output file, a multi-line task
  inside single quotes, and `cd <root> && git diff` / `git -C <root> diff` under verify.
- **status-guard** (DEC-068) reads the `[EXECUTION RESULT]` `status` and `verification`
  fields, not prose; it no longer warns on "setelah selesai, ...".
- **Commit gate** recognises `git.exe commit` and a quoted path to git.
- **Hook robustness** (DEC-068). A hook exit other than 0 or 2 is logged and failed open
  instead of showing as a hook error; `session-bind` locks the registry so concurrent session
  starts keep every binding; a `.workflow/run.sh` symlinked outside the project no longer
  passes the gate; status-guard ignores a quoted or fenced `[EXECUTION RESULT]`.
- **Commands removed** (DEC-069). `/.refactor`, `/.review` and `/.compress` are gone. A
  refactor is planned and executed like any change (`/.plan`, `/.execute -y`, `/.verify`);
  `/.refactor` no longer edits outside the execute chain. Use Claude Code's own commands for
  a code review or a prose-file compression. An upgrade removes the installed copies unless
  you edited them. The hooks no longer know the three names: `task-events` stops recording
  them (older rows still read) and `graph-refresh` no longer runs on `[REFACTOR RESULT]`; a
  test keeps `task-events`' skill list equal to the `LOCAL:` registry.
- **Commit approval wording.** `/.commit` now says what the gate already did: only a prompt
  that asks to commit creates the approval, and a bare "yes" only carries it to the next
  turn. A commit proposed outside `/.commit` needs `/.commit` or "commit", not "yes".
- **Command descriptions** (DEC-069). Every `/.<name>` wrapper takes its `description` and
  `argument-hint` from its skill's header, so the command list says what each command does
  and what it takes; `tools/maintain/sync_skills.py --write` regenerates them and `--check`
  fails on a stale one.
- **Labelled anchors** (DEC-069). A ref written `[proof:core/x.py:200]` or
  `[proxy:core/a.py:5]` was read with the label's last letter as a Windows drive and
  reported uncertified, which lowered confidence for real files; the drive letter now has to
  start a word.

**Not done, by decision:** per-category recurrence thresholds (grounded claims carry no
category; categorised durable facts bypass recurrence already), and validators for
`/.review` and `/.memory` (no deterministic signal a hook could check; `/.review` was later
removed, DEC-069).
