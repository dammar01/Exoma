# v3.8.3

`/.provider` now offers the models that are actually available in the installed provider CLI,
not a manually refreshed shortlist that had fallen behind (codex already ships
`gpt-6.1-sol`, agy already ships `gemini-3.8-flash` and `claude-opus-5-5-*`, while the
shortlist stopped at the previous generation). The newest model becomes the first option, and the choice
can be typed directly without the picker (DEC-056). No breaking changes to
configuration; the new skill and command take effect after `install`.

Behavior details: [`docs/reference.md`](../reference.md) — "`/.provider` model catalog".

**Behavior changes noticeable after install:**

- The `/.provider` picker reads the catalog from the provider CLI: opencode (`opencode models` +
  the models.dev cache), codex (`~/.codex/models_cache.json`, only `visibility: list`), agy
  (`agy models`). At most 20 models, newest first; up to 10 are shown as a numbered
  list, and "Other" accepts a number from that list.
- "Newest": opencode = the latest `release_date` within the active model's `family`; codex =
  the smallest `priority`; agy = the highest version within the active model family. The newest model
  is marked "(Recommended)" and is still confirmed by the user — it is not written automatically.
- agy: `-low/-medium/-high` variants are folded into one model with effort = the variant. Apply
  writes the variant id (`claude-opus-5-5-high`) and `effort: null`.
- Effort validation on apply uses the live catalog, so models newer than the
  shortlist are accepted without a warning. The router and `validate_provider_config` still use the
  shortlist (no CLI spawn per call).
- CLI unreadable → the built-in shortlist (`models_source: static`). Live results are cached for 10
  minutes; `AI_PROXY_MODEL_CATALOG=static` turns off live reading.
- Direct mode: `/.provider <provider> <model> [effort] [routes]`, e.g.
  `/.provider codex gpt-6-luna low`. Validated the same way as the picker; rejected → reason +
  `next_action`, it does not fall back to the picker. The command description, `argument-hint`, and `/.help`
  mention this mode.
- `install.py --update-providers` (opt-in, DEC-057) brings codex and opencode
  installed via global npm to `stable_version`, never to a newer release. agy and CLIs
  from other package managers are reported, not changed. Failure → a warning with the
  pin-back command; `provider_update.json` in the backup directory records the before/after releases.
- `install.py --apply` on POSIX without `bash` on PATH is now rejected (exit 6), the same as
  Windows without Git Bash.

**Fixes:**

- Windows: console windows no longer flash on every prompt, edit, and Stop. The
  `task-events.py` hook (the replacement for `task-events.ps1` when hooks moved to Bash) called `git`
  without `CREATE_NO_WINDOW`; it is now hidden like `graph-refresh.py`. The
  `hidden-spawn` check now also scans `dist/config/claude/hooks/`. Installed hooks only
  change after `install.py --apply`.
- A dry run of `install.py --update-providers` no longer writes the provider version cache: versions
  are read fresh without being stored (`read_version(..., fresh=True)`); cache invalidation still
  happens only on apply.
- The live catalog parsers (opencode, codex, agy), the cache TTL, and the timeout/error fallback are now
  tested directly with synthetic payloads, not only with a fake reader.
