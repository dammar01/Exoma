# v3.8.2

The closing release before the feature freeze: no new features, only failure paths that
were previously silent or lax. The codex second agent turned out to be able to write files through its built-in
edit tool even when running `--sandbox read-only` — this is now closed and re-proven against the
real CLI. Every provider declares the read/write boundary that is actually enforced,
and agy gets a write warning. Provider thread ids are no longer silently lost on Windows,
and the integrity paths (manifest, `install --check`, e2e artifact scrub) fail closed. All
temp-and-replace writers now share the same retry, and a session locked by a dead worker
is freed by the next request (DEC-050). The
plan/approval contract of DEC-046 from 3.8.1 ships as well. No breaking changes to
configuration; the new prompt bundle takes effect after `install`/`upgrade`.

**Behavior changes noticeable after upgrade:**

- Codex calls carry `-c approval_policy="never"`: file patches by codex are rejected on both new
  calls and resumes.
- `/.doctor` with agy shows a second `WARNING`: agy can write to the project.
- Delegated results carry `meta.provider_boundary`; for agy also `meta.provider_write_warning`.
- Unwritable session storage fails the call **before** the provider runs
  (`session_capture_failed`); losing the thread mid-run shows up as
  `meta.session_persisted: false`.
- `install --check` reports manifest entries whose source file has been deleted; `doctor`
  turns corrupt manifest entries into an issue.
- e2e artifacts that cannot be scrubbed are deleted and withheld from the report and the reviewer.
- New features without an active plan are routed to `/.plan`; only `/.execute -y` from the user
  counts as approval (DEC-046).
- A different request on a session whose job has a dead worker (PID gone or reused)
  is no longer rejected with `job_already_running`: the old job becomes `failed` + `reaped`, and the new
  request runs. A live or stalled worker still rejects a different request (DEC-050).
- The fact/evidence store, cache, installer receipt/ledger, opencode prompt, `current/`
  screenshots, and e2e tagging no longer fail when the target file is being read by another process on
  Windows (DEC-050).

## Provider write boundary (DEC-048, CASE-019)

Codex's `--sandbox read-only` only restricts shell commands; its file-edit tool (`apply_patch`)
is governed by the approval policy. The adapter now sends `approval_policy="never"` on `exec` and
`exec resume`. Each provider bundle declares `boundary: {reads, writes}`; doctor and every
delegated result read the same declaration. An opt-in probe re-proves it against the real
CLI and uses codex quota.
Details: [docs/reference.md](../reference.md), "Choosing a provider";
[docs/runtime-contracts.md](../runtime-contracts.md).

## Provider thread and integrity (DEC-049)

Session and job records are written through `atomic_write_json`: a unique temp name, and `os.replace`
retried when Windows refuses because the file is being read by another process. The executor tests storage
before the provider runs, retries the save after the run, and names any loss that remains.
A corrupt manifest, a missing manifest source, and artifacts that fail to scrub no longer pass
silently.
Details: [docs/runtime-contracts.md](../runtime-contracts.md).

## Retry for all writers and dead-worker locks (DEC-050)

`atomic_write_text` gains `newline` and `fsync` options, `atomic_write_bytes` exists, and
`replace_with_retry` is public. Thirteen writers that used to do their own temp-and-replace
now use that helper, each keeping its own error policy: the store and installer
raise, the cache and the `current/` mirror swallow. e2e tagging uses its own staging because the
file-identity check must happen right before the move; it only borrows the retry.
`submit` for a different request calls `release_dead_session_lock` under
`capacity_guard`, the same guard as recovery, so an identical request that is in
recovery cannot be preempted.
Details: [docs/reference.md](../reference.md), "Async jobs & recovery".

## Tests

The default suite now runs two checks that were previously registered in `SUITES` but not
called by `scenario` (`error-types`, `redaction-boundary`); without that the registration guard
stops the suite before any test runs. New checks: `session-persistence`,
`atomic-write-held`, `provider-boundary`, `manifest-malformed`, `codex-write-probe` (opt-in),
`atomic-helpers`, and `atomic-writers`. `scenario` step 8 tests a different request on a
session with a dead worker.

## Known, not yet addressed

- `installer/rollback.py` still uses its own temp-and-replace without retry.
- The opencode prompt writer is not in the held-file check; only the launch check exists.
- The `init` message for codex still says that `--sandbox read-only` restricts writes, without
  mentioning `approval_policy`.
- The `/.verify` reviewer does not see `runtime_tests`, so a clean verify can end
  `incomplete`.
- `claude -p` cannot complete delegated commands: the runner must be a background task, and the
  process exits before the task finishes (CASE-020).
