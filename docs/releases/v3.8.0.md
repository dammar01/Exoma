# v3.8.0

Five themes: workflow latency measured per component (graph, reuse, effort, provider thread);
`/.verify-browser` records network metadata and prefers proven selectors;
per-task telemetry (skill, edit, commit) without extra prompt instructions; `clean` removes
guard locks of dead sessions; and research questions become YAML records linked in both directions.
No breaking configuration changes. The new `task-events` hook only becomes active after
`install`/`upgrade`.

**Behavior changes noticeable after upgrade:**

- The auto-intent runtime gate is now actually active. `intent-gate-set` had been reading
  a `user_prompt` field that Claude Code never sends, so the gate marker was never
  set. Now, after a prompt that maps to a delegated command, gather tools are
  blocked until `.workflow/run` is called (escape: `WORKFLOW_LOCAL_MODE=1`).
- `--only-command` mode now limits the whole workflow block to when a command is invoked:
  plain chat follows the user's CLAUDE.md, including language style (caveman is no longer the default in
  this mode).
- The `settings.json` template no longer plants `model`, `enabledPlugins`,
  `extraKnownMarketplaces`, `effortLevel`, `permissions.defaultMode`. Existing installs
  are unchanged; new installs no longer get them.

## Latency and telemetry

- Usage contract v3: `effort`, `provider_resumed`/`provider_thread_changed`, `reuse_outcome`,
  `graph_status`/`graph_ms`. `report` adds `evidence_reuse`, `provider_cache`,
  `provider_threads`, `by_effort`, `graph_leads`. `by_effort` counts all commands and
  takes the median only from measured values. See `docs/reference.md` (`report`).
- Graph refresh moves entirely to the `graph-refresh` Stop hook and runs separately from the
  turn; graph readers do not wait for the lock (DEC-012, CASE-008).
- `verify-browser` records once per command whether a refresh is running alongside it
  (`refreshing`/`available`/`absent`), without a leads lookup.
- Per-task telemetry (DEC-015, revised by DEC-020): `tasks.jsonl` is filled by the runtime (delegated
  commands, with the declared verdict and the derived verdict) and the `task-events` hook
  (local skill loaded, file edit, commit that moves HEAD). `report` → `tasks`:
  `completed` only after a verify whose derived verdict is `pass`; a commit is recommended afterwards
  but does not close the task. The `ready_to_commit` and `unverified_closed` states are removed. See
  `docs/reference.md` (Task telemetry) and `docs/runtime-contracts.md` (Task events).

- The `task-events.ps1` hook no longer loses events on Windows PowerShell 5.1 when git writes
  to stderr (project without git, repo with dubious ownership); the hook tests now use `powershell`
  5.1, the same as the installed one. JSONL readers (usage, quality, tasks) skip lines
  truncated in the middle of a multi-byte character instead of crashing `report`; the e2e
  knowledge store reads with the same rule.
- `graph-refresh`: a refresh that times out is still recorded as `timeout`, and a graph that cannot
  be parsed is never recorded as `refreshed`; a stale lock is only removed if its token is still the same
  (two sessions can no longer run two `graphify update` at the same time); `target/` is skipped.
  A timeout kills the whole graphify process tree, not just its wrapper.
- The `task-events` hook no longer runs on every `Read` and `Bash` (~450 ms per PowerShell
  spawn on Windows; `Bash` was hit twice). Skills are read from the prompt (`/.<name>`) and the
  `Skill` tool, commits from HEAD moving between turns (`UserPromptSubmit`/`Stop`).
  Event v2. Install removes the old registration from `PreToolUse`.
- Usage contract v4: `e2e_stage` (`draft`/`run`) and `browser_seconds`. A browser run that
  ends before review no longer writes a usage line — previously that line, without `prompt_id`,
  provider, and tokens, was counted by the statusline as one extra call and by `report`
  as a judged verify plus a zero-token verification in the baseline. `report` drops
  old lines of that shape; `verify-browser` drafts leave the `evidence_reuse` denominator.

## Install

- The first install into CLAUDE.md/AGENTS.md writes **only** the marker block; text outside the marker
  is no longer written along with it and can no longer be confused with user text.
- `install.py --uninstall` (dry run, then `--apply`): removes the workflow block from every instruction
  file while keeping user text, unedited workflow files, and the workflow hooks and
  `statusLine`. It writes a receipt, so `--rollback` undoes it.
- The block in `AGENTS.md` (opencode, codex, agy) only applies to runtime calls (instructions
  opened with `[WORKFLOW_AGENT]`); using that provider directly no longer follows the second agent rules.
- Documentation: `docs/team-guide/installation.md`, `docs/team-guide/whats-included.md`;
  `docs/reference.md` has a table of all flags, targets, and hooks. The README now shows two
  install lines (`--auto-intent` / `--only-command`), uninstall, and rollback.
- An unpaired block marker (START without END or the other way round) causes the install of that file
  to be rejected with a clear message, instead of adding a second block.
- Uninstall cleans `settings.json` (including one with a BOM) **before** deleting the hook scripts;
  if the settings cannot be read, the scripts stay so hooks do not point to a missing file.
- `doctor` warns about the old `Personal Global Config (v…)` header outside the
  `~/.claude/CLAUDE.md` marker: a leftover of an old install, now user text, safe to delete manually.

## Codex on Windows

- A codex Windows sandbox failure (`windows sandbox failed ...`) is now `error_type:
  sandbox_unavailable` with ordered fix steps, not `unknown` (CASE-015).
  The runtime does not downgrade the sandbox.
- The codex version is recorded in call meta, usage lines (`provider_version`), and `doctor`.
- `thread_changed` (codex, agy) no longer fires for a resume call that fails before
  naming any thread.
- Tested provider releases: `stable_version` per provider in `config/providers.py`
  (opencode 1.18.34, codex 0.154.0, agy 1.1.13). The version is read for **all** providers; the usage
  row carries `provider_version_status` (`stable`/`untested`/`unreadable`) and `doctor`
  warns about `untested` releases. Advisory, not blocking. Bisect on Windows: codex
  after 0.154.0 up to 0.160.0 fails to resume a thread (`sandbox_unavailable`), a new
  thread still works (CASE-016). Pin back: `npm i -g @openai/codex@0.154.0`.
- `codex --version` and the version read of other providers are time-limited and kill the process tree
  on timeout (`.cmd` shims on Windows).

## Test

- The suite no longer depends on the machine's provider choice: a `config/second_agent.seed.json` seed
  (git-ignored) with provider codex made `scenario` and `continuation` fail on that machine
  only. The test workspace now always comes from `second_agent.example.json` (`test-isolation`).

## `/.verify-browser`

- Ordered request metadata for every request — type, size, duration, difference between runs —
  without body or headers (DEC-014).
- Proven selectors (`data-e2e` quoted from source, or one that already passed a previous
  run) are ranked above role and label; failing ones are demoted and then retired
  (DEC-016). Only candidates the browser actually tried can fail: a step that fails
  before resolve (not ready, exception) no longer demotes a proven selector. A `proven`
  selector missing from a stable page is classified `app`, like a sourced selector.
- Usage recording re-audited (draft + continuation + repair, run + review continuation):
  one row per invocation, tokens per row equal the provider report, `browser_seconds` only
  on the last row, statusline call count = `report.calls`. No miscounts since
  8d2d42b; old ghost lines (209, before 8d2d42b) are still filtered by `report`.

## Verify

- The second agent no longer runs tests. The main agent picks tests from the diff and dependents into
  the per-session `verify/tests.json`; the runtime runs them (only prefixes in
  `commands.verify_test_commands`, no shell) and writes the results into `[VERIFICATION]`:
  a failed test = blocking, a missing request or a rejected command = `not_verified`. **Behavior
  change:** verify without `tests.json` is now `incomplete`, and the default allowlist is empty —
  fill `commands.verify_test_commands` in each project's `.workflow/config.json`.
- Usage: `tests_requested`, `tests_run`, `tests_failed`, `tests_seconds`.
- Hardening: `reason`/`command`/`detail` from `tests.json` can no longer forge a
  `[VERIFICATION]` section through a newline (an `incomplete` verdict could briefly become `pass`); a test timeout
  kills the whole process tree (previously verify could hang forever on Windows while
  holding the session lock); `tests.json` is only consumed after the results are merged (a recovery run still
  finds it); a boolean timeout is ignored.
- Empty allowlist: the prompt line "jangan jalankan test runner" ("do not run the test runner") is not sent, and `doctor`
  warns about it. The gate hook allows main_agent to read `git diff --name-only`/`--stat`
  and `.workflow/config.json` and to write `verify/tests.json` before `.workflow/run verify`
  — previously the skill told it to pick tests from the diff while the gate blocked it.

- The "tidak ada temuan" ("no findings") section is accepted in the spellings agents write (`none.`, `none; all
  clean`, `tidak ada`, …) so a clean verify no longer becomes `fail`; continuation asks for
  `- none` (DEC-018, CASE-009). In the E2E reviewer, multi-line items still only accept the old
  form, so `- none.` does not hide a finding on the next line.

## Workspace

- `clean` removes `sessions/<id>/runtime/lock.guard` belonging to sessions without a live runtime lock;
  a guard currently held stays. Race-safe on Windows (the OS rejects the delete) and
  POSIX (the holder waits to reopen the path) (DEC-013, CASE-007).

## Benchmark calculation contract

- Metric registry (`core/audit/metrics.py`, rendered in `docs/evaluation/metrics.md`): every
  number has an ID and version (`outcome.solved@1`), definition, denominator, missing-data rule, and
  statistical convention. Terms that used to be overloaded ("task", "saved") are now separate IDs.
  Existing formulas are unchanged: `measure_task_outcomes` produces exactly the same CASE-012
  numbers (97 tasks, 68 solved).
- `report()`, `measure_real_use.py`, and `measure_task_outcomes.py` print a `provenance` block
  (metric version, tool commit, parameters, input hash without paths). `measure_task_outcomes` thresholds
  that used to be hard-coded are now flags with the same defaults.
- New research rule (CONTRACT.md §15, DEC-026): numbers from registered metrics are quoted as
  `<id>@<version>` together with their provenance.
- Measurement tools for all users (DEC-027): anyone who installs the workflow can run
  `measure_real_use.py`/`measure_task_outcomes.py` on their own project; `--export <file>`
  writes aggregates + provenance that may be shared, rejected if it contains paths or project names.
  Guide: `docs/team-guide/measure-your-use.md`. Recomputation still only on the data owner's
  machine.
- `outcome.context_saved@2`: definition corrected to the formula that actually runs (fresh −
  returned; reasoning reported separately) and the tests now match the implementation, not only
  the docs. Together with `real_use.delegated_call@2`: one usage row belongs to one transcript (the
  earliest one that binds its session id). On all data up to 2026-10-04 the result is identical to @1
  (no session id bound twice).
