# v3.8.1

A fix release on top of 3.8.0, from branch review, real use, and a CI failure on Linux.
The pre-flight gate is more precisely targeted: skills may be read, two small Reads per delegation
pass, and task notifications no longer set the gate. Graph refresh runs without a time limit
under a heartbeat lock. `/.verify-browser` records selectors across ids and from drafts
that write `side_effect: "none"`. `install --check` checks the boundary matching the project's
provider, and metrics export checks project names at every length. `.ps1` hooks are now correct under
non-Windows `pwsh`. On the research side, a new charter frames agent delegation as a
resource-allocation problem (RQ-16, RQ-17, LIT-001). No breaking changes to
configuration. New hooks and skills take effect after `install`/`upgrade`.

**Behavior changes noticeable after upgrade:**

- Reading `~/.claude/skills/<name>.md` passes while the gate is active, so workflow skills can be read
  before dispatch.
- `proven` selectors recorded on id-bearing routes before this release lose their rank
  until one clean run proves them again on the `:id` route.
- Exports that contain a short project name as a word are now rejected.
- `install --check` in a codex project no longer reports `MISSING opencode/opencode.project.json`.
- While the gate is active, two small (≤ 200 lines) Reads of project files per delegation pass.
- graphify is no longer time-limited; `GRAPH_REFRESH_LIMIT_S` is ignored.
- A passing browser run now also records selectors from drafts that write `side_effect: "none"`.
- Background task notifications no longer set the delegated gate.

## Export and provenance (DEC-038)

- Names of projects contributing data are matched as whole words at every length; previously
  names of ≤2 characters were skipped.
- Keys under `per_project` and `by_project` must be tool labels (`PA`,
  `Project AB`); folder names there are rejected by their shape.
- `tool_commit` returns `null` when `git status` fails, instead of a hash that looks
  clean.

Details: [docs/evaluation/metrics.md](../evaluation/metrics.md).

## Pre-flight gate (DEC-039)

Reading a skill definition passes for every delegated command: an absolute path without `..`, `.md`, the file
exists, and its real path (symlinks followed) is inside `~/.claude/skills`. Both hook flavors are identical.
The `.ps1` flavor compares paths with the running OS's separator, so `pwsh` on Linux no
longer rejects a valid skill (found by Linux CI, reproduced with pwsh 7.4 on Linux).

`graph-refresh.ps1` under non-Windows `pwsh` (the CI path, not an installation: POSIX uses the
`.sh` flavor) now starts the worker without `-WindowStyle` and with output redirected,
reads a corrupt lock with `-ErrorAction Stop`, and sees the hidden `.refresh.lock`
with `-Force`. Previously the worker never ran and a half-written lock was treated as
abandoned.
Details: [docs/reference.md](../reference.md), "Pre-flight gate".

## `/.verify-browser` (DEC-040)

Proven-selector routes fold identifier segments into `:id` with the same rule as the
network ledger: `/users/123/edit` and `/users/456/edit` are one route. A slug stays its own route.
Details: [docs/runtime-contracts.md](../runtime-contracts.md).

## Selector knowledge from explicit drafts (DEC-044)

Browser knowledge now reads `side_effect: "none"` as not a write, the same as the
spec validator. Previously a draft that wrote `"none"` on every step (as current drafts do)
never recorded selectors, so `proven` and `proven_scope` did not grow from passing
runs. Found from a real passing browser run that recorded not a single selector.

## Task notifications do not set the gate (DEC-045)

`intent-gate-set` ignores prompts that start with `<task-notification>`: background task
notifications no longer set the delegated marker (a word such as "analyze" in the task description used to
set a gate nobody asked for) and do not clear a marker set by a user prompt.

## Precision Read while the gate is active (DEC-043)

While the delegated marker is active, the main agent may read a small slice itself for
file:line attribution, as `CLAUDE.md` already allowed: a project file outside `.workflow/`, at
most 200 lines (`limit` ≤ 200, or a file that is actually that short), at most 2 per
marker. A 3rd Read, a longer span, Grep, Glob, MCP, and the shell stay blocked, and the block
message states the rule. Found in real use: the gate rejected a 210-line Read that the
prompt allowed, and the agent paid for one extra delegation.

## Graph refresh without a time limit (DEC-042)

The graph-refresh worker runs `graphify update` to completion, with no time limit and without
killing it; `GRAPH_REFRESH_LIMIT_S` is no longer read and new rows are never `timeout`.
While graphify runs, the worker rewrites `beat` in `.refresh.lock` every 15 seconds; the lock
is considered held while `beat` < 120 seconds, regardless of its age. Old locks without `beat` still
use the 15-minute rule. `doctor` reports this lock and suggests a step when a refresh
has been running ≥ 1 hour or its lock is stale; `clean` removes only stale locks and never
kills a process. A hung graphify holds the graph until the user stops the process.

## Installer (DEC-041)

`install --check` inside a workspace checks only the project boundary of the provider that
the project runs, the same one `init` installs. Previously codex projects were always DRIFTED
because of an `opencode.json` that no command ever installed. Projects without an explicit provider
are still checked as opencode. The installer check in `tools/e2e` now writes the project's
`second_agent.json` from the example before `init`, so the machine's provider seed no longer
decides the result — the two e2e failures recorded in [v3.8.0](v3.8.0.md) are gone.

## Provider

A `<cli> --version` that finishes without a semver is now recorded as `provider_version: null`, matching the
reference; previously the first line of stdout (a banner) was stored as the version. Its status was already
`unreadable` before, so the `doctor` warning does not change.

## Verify

The `verify` skill asks for a `tests.json` containing `commands: []` with a reason for projects without a
test suite, instead of skipping that file (which became a runtime gap with a nonzero exit).
The runtime is unchanged.

## Research

- DEC-038, DEC-039, DEC-040 new; each `not_validated`.
- New research charter ([docs/research/CHARTER.md](../research/CHARTER.md)): agent delegation is studied
  as resource allocation, i.e. when one more delegated execution is still worth its
  tokens, latency, human intervention, and coordination. New questions RQ-16 (optimal
  decomposition) and RQ-17 (scaling the number of executions); RQ-01, RQ-02, RQ-13 carry the rest. Literature
  LIT-001 (a harness with a higher abstraction) is recorded as a `conceptually_related` reference
  that this project does not follow; its metadata and abstract were verified against the arXiv API. The core hypothesis is still a draft.
- DEC-035 correction: the generic 3.8.0 Chromium smoke was indeed run and passed, but it did not
  touch selector knowledge, so it is not evidence for DEC-035. The claim in
  [v3.8.0](v3.8.0.md) holds for the runner, not for selector knowledge.
- DEC-032 correction: the gate's write block applies to the `run|check|inspect` runners with any
  extension, not only `.ps1`/`.sh` as its decision text says; the code is unchanged.
