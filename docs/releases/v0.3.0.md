# Exoma 0.3.0

Host release. Agy (Antigravity CLI) joins Claude Code as a primary-agent host, the decisions
both hosts enforce move into one shared hook module, and the Agy install becomes all or
nothing, with an uninstall that takes out exactly what it added. Two defects found while
staging 0.2.0 on macOS are fixed.

## Hosts

- Agy is a second host. Where `~/.gemini` exists, `exoma install` adds the `EXOMA-HOST` block to
  `~/.gemini/GEMINI.md` and the `exoma` hook to `~/.gemini/config/hooks.json`; the wrapper
  `~/.claude/hooks/agy-host.py` maps the runtime's gates onto Agy's hook contract. It fails open
  on any error, as Agy fails the tool when a hook fails.
  ([reference: hosts](../reference.md#hosts))
- Write root and scope, commit approval, the user's approvals, the pre-flight marker and the
  `[EXECUTION RESULT]` claim live once, in `~/.claude/hooks/workflow_policy.py`. The Claude
  hooks keep only Claude Code's payload and output handling; one that cannot import the module
  (a partial install) exits 0 without acting.

## Install and uninstall

- The Agy instructions and hook install together or not at all. An interpreter or home path
  Agy's unquoted hook command cannot carry (a space, or a `cmd.exe` metacharacter — pipx on
  macOS lives under `Application Support`), or a `hooks.json` that is not a JSON object, refuses
  both files; an `EXOMA-HOST` block an earlier install left is cut, backed up and receipted.
  `--check` reports the refusal and a missing or drifted `exoma` entry.
- `--uninstall` takes the `exoma` name out of `hooks.json` and keeps every other hook; a file
  that held only `exoma` is deleted. An unreadable `hooks.json` is left as is, with a warning,
  and the hook scripts stay so nothing points at a missing file. `--rollback` undoes it.
  ([reference: uninstall](../reference.md#uninstall))

## Workspace

- The project root written into `.workflow/run.sh` and `inspect.sh` is resolved first. On macOS
  a project under `/var` (a symlink to `/private/var`) no longer shows drift when `upgrade` is
  called with the other spelling.
- The interpreter pin `.claude/hooks/python.path` is read from `AGENT_HOME` when it is set, the
  home the installer wrote it to; generated scripts no longer embed the real home's pin under a
  test or staging home. `EXOMA_HOME` still moves runtime data only.

## Upgrading

- `exoma install --apply` adds the Agy host only where `~/.gemini` exists; a Claude-only machine
  gets no new directory.
- `exoma upgrade` in each project regenerates `run.sh`/`inspect.sh` once if their root was
  written unresolved.

## Not run for this release

Recorded per `RELEASE.md` step 6 once the gate runs: the e2e smoke, the delegated `--full` run,
a live Agy session, and staging in agent-workflow.
