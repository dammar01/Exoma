# Exoma 0.3.0

Host release. Agy (Antigravity CLI) joins Claude Code as a primary-agent host that the install
sets up only when chosen, entirely under Agy's own `~/.gemini`; the decisions both hosts enforce
live in one shared hook module; the bundle is laid out by role (`hosts/`, `providers/`), and the
Agy second agent becomes an Agy custom agent. Two defects found while staging 0.2.0 on macOS are
fixed.

## Hosts

- The install asks which main-agent host to set up — `claude`, `agy`, or `both` — on the first
  `exoma install --apply` from a terminal, or takes `--host`; a non-interactive first install is
  `claude`. The choice is kept across upgrades, and a host dropped from it has Exoma's files taken
  back out. An install from before the choice keeps what it had (Claude, plus Agy where its hook
  was installed). ([reference: host choice](../reference.md#detail-host-choice))
- Agy is a second host, installed under Agy's own directories only: the `EXOMA-HOST` block in
  `~/.gemini/GEMINI.md`, the `exoma` hook in `~/.gemini/config/hooks.json`, and under
  `~/.gemini/antigravity-cli/` the contract (`exoma/CONTRACT.md`), the hook wrapper with the policy
  and intent map beside it (`exoma/hooks/`), and every workflow command as an Agy skill
  (`skills/.<name>/SKILL.md`, answering to `/.<name>`). No Agy file reads `~/.claude`. The wrapper
  maps the runtime's gates onto Agy's hook contract and fails open on any error, as Agy fails the
  tool when a hook fails. ([reference: hosts](../reference.md#hosts))
- The runner is started through this machine's bash by its path (`& '<Git Bash>'` on Windows,
  where Agy runs commands through PowerShell and a bare `bash` can be WSL's); the gate refuses a
  bare `bash` there and names the right command.
- Permission rules come with the Agy host: they let the runner run without an approval prompt
  and the runtime write its data directory from Agy's sandbox. `--no-agy-permissions` leaves them
  out and is kept. Only the rules Exoma added are recorded and ever removed; a rule the user
  already had is never claimed.
- `/.doctor` reports each chosen host's files (`checks.hosts`; `both` reports both). In Agy it
  also observes the session — skills registered, hooks running, the runner without a prompt, and
  why it failed if it did.
- Write root and scope, commit approval, the user's approvals, the pre-flight marker and the
  `[EXECUTION RESULT]` claim live once, in `workflow_policy.py`, installed beside each host's
  hooks. The Claude hooks keep only Claude Code's payload and output handling; one that cannot
  import the module (a partial install) exits 0 without acting.

## Providers

- The agy second agent's contract is an Agy custom agent,
  `~/.gemini/config/agents/exoma-second-agent/agent.md`, selected per call with `--agent` once
  installed; an Agy host session no longer carries it. It used to go to `~/.agy/AGENTS.md`, which
  Agy does not read; that block is cut on install, the user's own text kept.
  ([reference: choosing a provider](../reference.md#choosing-a-provider--and-its-security-consequences))

## Install and uninstall

- The bundle is laid out by role: `hosts/<name>/` and `providers/<name>/`, so a host and a
  provider may share a name. Keys an older install recorded are read as their current form, so
  stale cleanup, `--uninstall` and doctor still recognise its files.
  ([reference: bundle layout](../reference.md#detail-bundle-layout))
- The Agy instructions and hook install together or not at all. An interpreter or home path
  Agy's unquoted hook command cannot carry (a space, or a `cmd.exe` metacharacter — pipx on
  macOS lives under `Application Support`), or a `hooks.json` that is not a JSON object, refuses
  both files; an `EXOMA-HOST` block an earlier install left is cut, backed up and receipted.
  `--check` checks the chosen hosts and reports the refusal, a missing or drifted `exoma` entry,
  and a missing permission rule.
- `--uninstall` takes the `exoma` name out of `hooks.json` and keeps every other hook; a file
  that held only `exoma` is deleted. An unreadable `hooks.json` or `settings.json` is left as is,
  with a warning, and its hook scripts stay — also when a host is dropped from the choice — so
  nothing points at a missing file. `--rollback` undoes it.
  ([reference: uninstall](../reference.md#uninstall))

## Workspace

- The project root written into `.workflow/run.sh` and `inspect.sh` is resolved first. On macOS
  a project under `/var` (a symlink to `/private/var`) no longer shows drift when `upgrade` is
  called with the other spelling.
- The interpreter pin `.claude/hooks/python.path` is read from `AGENT_HOME` when it is set, the
  home the installer wrote it to; generated scripts no longer embed the real home's pin under a
  test or staging home. `EXOMA_HOME` still moves runtime data only.

## Upgrading

- `exoma install --apply` keeps the hosts the last install had. Pass `--host agy` or `both` to add
  Agy; on an Agy machine the old `~/.claude/hooks/agy-host.py` registration is replaced by the one
  under `~/.gemini`. Run `/.doctor` in Agy afterwards.
- `exoma upgrade` in each project regenerates `run.sh`/`inspect.sh` once if their root was
  written unresolved.
