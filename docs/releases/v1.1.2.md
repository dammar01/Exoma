# Exoma 1.1.2

Candidate preparation for the macOS cleanup failure observed while publishing v1.1.1.
This page does not certify native release acceptance or publication.

## Changes

- **Coherent Darwin inventory.** Cleanup reads process status, microsecond start time,
  native parent and lifetime identifiers from one combined libproc record. The query
  includes zombie processes and does not require an executable path. Live-process
  identity and executable verification keep their existing semantics.
- **Conservative fallback.** A denied or unavailable combined query retains independent
  native lineage when readable. Missing identity remains explicit uncertainty; equal
  coarse `ps` timestamps and PPID 1 do not prove that a process is unrelated. Terminal
  ancestry stays in the ownership graph because an exited parent can leave surviving
  descendants. Unknown, reused or owned ancestry still prevents cleanup acceptance.
- **Bounded diagnostics.** Cleanup evidence includes an allowlisted numeric native
  status alongside the existing bounded generation/query diagnostics.

The shared ownership classifier also governs delegated-worker completion and cancellation.
There is no provider-adapter or public result-contract change in this candidate.

## v1.1.1 publication record

The public `v1.1.1` tag remains at commit
`2b9d4ce0b39a317fa106ef7156b7864cd637cb68`; its tag and release notes are preserved.
[Publish run 44256600723](https://github.com/dammar01/Exoma/actions/runs/44256600723)
failed in [macOS / Python 3.13 / pip](https://github.com/dammar01/Exoma/actions/runs/44256600723/job/134639670326).
The actual candidate A-to-B transition succeeded with worker independence verified.
The separate package no-op then stopped at `cleanup_pending`: its command exited 0,
the child was reaped and its process group was absent, but native ownership could not
be established for seven inventory rows whose identity/lineage queries had failed.
The publication job was skipped by its CI dependency.

The saved receipts do not establish whether those rows represented zombie processes,
fully reaped processes or PID reuse. This candidate addresses the demonstrated loss
of native inventory evidence; it does not treat unavailable identity as cleanup proof.
No independent claim about PyPI publication state follows from that workflow record.

## Validation

Deterministic regressions cover the native structure decoder and zombie-inclusive
query, terminal foreign lifetimes, permission-restricted lineage fallback, unknown
processes and reused/owned ancestry. Worker lifecycle checks exercise completion,
retained cleanup uncertainty and subsequent update admission using the shared owner.

Native ABI availability and behavior still require macOS execution on the final
candidate commit. Require both the actual A-to-B transition and the separate no-op
under the strict manager/Python matrix; a contained run cannot substitute. New-commit
release evidence, including the required Windows native gate and staging, remains
pending under [RELEASE.md](../../RELEASE.md). Earlier v1.1.1 reports do not certify this
candidate. No v1.1.2 tag or publication is part of candidate preparation.
