# Exoma 1.0.0b1

A pre-release of 1.0.0, published so the release can be tried on real work before it becomes
the version `pip install exoma` and `uv tool install exoma` pick. Its contents are the 1.0.0
release: what changed, how to upgrade from 0.3.0 and the known limitations are in
[the 1.0.0 notes](v1.0.0.md). Nothing here is a separate feature.

## Installing the pre-release

Installers keep choosing the stable 0.3.0 unless the pre-release is asked for:

```bash
uv tool install exoma==1.0.0b1          # or: uv tool install --prerelease allow exoma
python -m pip install --pre exoma       # or: python -m pip install exoma==1.0.0b1
exoma install
```

A uv tool installed with `exoma==1.0.0b1` keeps that requirement, so `exoma update` (which
runs `uv tool upgrade exoma`) stays on 1.0.0b1 rather than moving to a later release. Once
1.0.0 is out, move to it by name: `uv tool install --force exoma` (or
`python -m pip install --upgrade exoma`), then `exoma install`. On a pip install, `exoma update`
runs `pip install --upgrade exoma` without `--pre`; how pip treats an installed pre-release
there has not been checked, so install the version you want by name. To go back to the stable
release, install it by name (`uv tool install --force exoma==0.3.0` or
`python -m pip install exoma==0.3.0`) and run `exoma install` again.

## Release tooling

- `tools/maintain/stamp_version.py` reads a PEP 440 pre-release suffix (`a`, `b`, `rc`) as
  part of the version. It used to match only `X.Y.Z`, so stamping `1.0.0b1` a second time wrote
  `1.0.0b1b1` and `--check` failed. The runtime compares versions only for equality, so a
  pre-release string needs nothing else.
